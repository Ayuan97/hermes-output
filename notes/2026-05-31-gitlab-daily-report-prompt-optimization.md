## 优化背景

主子是公司技术负责人，每天 18:00 收到 GitLab 日报。原 prompt 存在多个问题：

1. **时间窗口错误** — 使用「最近 24-72 小时」滑动窗口，周一混入周末数据
2. **输出啰嗦** — 列分支名、项目 ID、提交数量、Pipeline 状态，技术负责人不想看
3. **无提交还发报告** — 周日发空报告纯属浪费
4. **路径偏离** — 报告存到了 hermes-agent 仓库而非 hermes-output

## 优化历程

### 第 1 版（奴才自行修复）

- 时间窗口改为「今天北京时间 00:00 到现在」
- 简化输出为「项目推进」+「人员动态」两段
- 无提交 → [SILENT]
- 但主子反馈「还不够好，去找 Claude 聊」

### 第 2 版（跟 Claude 聊第一轮）

Claude 给的主要改进：

- 加了【项目】【人员】两个轻量分节，不会混淆两种行
- 流程明确：项目聚合 + 人员聚合都要做
- 一人跨多项目合并到一行，用 ；分隔，不刷屏
- 禁项更全：补了「百分比」「正常推进」「提交密集」等伪进度表述

### 第 3 版（最终版，主子亲自调整后）

主子看了第 2 版的示例输出后提出：

- **去掉人员维度** → 改为「提交排行」
- **项目部分只写做了什么**
- **排行包含**：提交次数、代码量（+新增行 -删除行）
- **按代码量降序**，只列有提交的人

最终输出格式：

```
📅 6月1日 周一 · 帖子工坊收尾、计费全链路打通

【项目】
justus-content-core：字幕擦除计费接入、智能体定价API上线
lnct-web：种草笔记裁剪完成、借图发帖实时进度

【提交排行】
🥇 赵文龙：23 次提交 / +1847 -521
🥈 郭强：19 次提交 / +1203 -438
🥉 赵华鹏：8 次提交 / +692 -215
4. hd：5 次提交 / +341 -89
```

## 最终 cron 配置

- 时间：每天 18:00（北京时间）
- 路径：`~/Desktop/go/hermes-output/summaries/{日期}-company-gitlab-daily-report.md`
- 工作目录：`~/Desktop/go/hermes-output`
- 无提交 → [SILENT]

## 经验教训

1. **路径必须写绝对路径**，否则 cron 默认存到 agent 自己目录
2. **时间窗口必须用「今天 00:00」而非滑动窗口**，否则周末数据污染周一报告
3. **跟 Claude 聊设计问题时，要一次性说清楚所有约束**，否则得来回几轮
4. **先出 mock 再上线**——第 2 版本来已经在 cron 里更新了，但主子不满意，说明应该先给主子看效果再 deploy

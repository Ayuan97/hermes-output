## 结论

主子的 Claude Wiki 是一个基于 Markdown 文件的长期知识库，不是普通 RAG。它把值得复用的经验、问题、方案、项目分析沉淀成结构化页面，并通过 `index.md`、交叉引用和 `log.md` 维持可检索、可追踪的知识网络。

## 目录结构

```text
sources/    → 原始资料，只读不修改
projects/   → 项目资料：架构、决策、踩坑、交付说明
issues/     → 问题记录：症状、根因、解决方案
repos/      → 开源项目分析与可借鉴点
tech/       → 技术分析：原理、对比、判断
index.md    → 全站目录，每次入库必须更新
log.md      → 时间线日志，append-only
CLAUDE.md   → Wiki schema 和写入规则
```

## 三类核心操作

### 1. Ingest：存入知识

触发方式：用户明确说 `ingest xxx`，或任务结束后有值得长期保存的成果。

典型流程：

1. 提炼内容，去掉临时对话噪声。
2. 判断应该放进 `projects/`、`issues/`、`repos/`、`tech/` 等哪个目录。
3. 创建新页面，或更新已有页面。
4. 补充相关页面的交叉引用。
5. 更新 `index.md`。
6. 在 `log.md` 追加一条记录。

### 2. Query：基于 Wiki 回答

触发方式：用户问到 Wiki 里可能已有记录的内容。

典型流程：

1. 先读 `index.md` 定位相关页面。
2. 读取并综合多页内容。
3. 基于已有知识回答。
4. 如果答案本身也有长期价值，再建议回写。

### 3. Lint：健康检查

触发方式：用户说 `lint`、`检查 wiki` 或类似指令。

检查项包括：

- 内容是否矛盾
- 页面是否过期
- 是否存在孤儿页
- 交叉引用是否缺失
- `index.md` 是否漏登记
- `log.md` 是否漏记录

## 什么时候值得写入

不需要每次聊天都保存。适合写入的内容包括：

- 解决了非平凡 bug
- 完成关键决策或架构变更
- 分析了开源项目并总结可借鉴点
- 完成一项技术调研
- 形成了可复用流程、脚本、排障方法

## 和 RAG 的区别

```text
RAG：每次检索片段 → 拼进上下文 → 用完即丢
Wiki：知识被整理成页面 → 建立链接 → 持续累积 → 越用越厚
```

这个 Wiki 的价值不在于“能搜到”，而在于知识经过人工/代理整理，能长期复用，并且能被后续 Claude/Hermes 会话按结构读取。
